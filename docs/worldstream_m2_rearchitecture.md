# M2 camera boundary and on-demand world state

The existing window executor, dependency planner, cache versions and v2 window
cost table remain available. Defaults keep the prior window/M1 continuity service.
No approximate reuse runs in Auto. The original EVA forward and weights are unchanged.

`worldstream_m2_camera_auto.py` opts into `reuse_boundary='camera'`. EVA treats
cameras as independent batch sequences, so an unchanged camera input has no
attention dependency on other cameras. A hit still requires full finite,
same-coordinate input equality, matching scene/camera order, weights, positional
buffers, execution policy, shape, stride and cache version. Sampling only rejects.
The cache owns its input and output; assembled features retain the original full
output stride. A cached camera keeps its actual computation frame/timestamp while
its enclosing request context advances. Detection, Map, temporal memory and LLM
execute on every current request, with current pose/time. No head outputs are cached.

Partial camera subsets change GEMM/FlashAttention batch shapes and can change
floating results. They are experimental under `mode='exact'`. Formal Auto uses a
separate checkpoint/layout/hardware-specific camera cost table and requires actual
downstream quality approval plus measured GPU and wall savings. Missing or
incompatible records use the complete original backbone. The table generated by
this experiment deliberately does not promote partial subsets from feature L2 alone.

`cheap_gate=True` enables a sampled rejection before M1. Every sampled difference
is evidence against full-window equality; matching samples never authorize a hit.
The full current image is snapshotted for the next gate. Read/clone and scalar CUDA
synchronization costs are included in service timing. Rejected window requests
bypass sparse planning and execute the original full backbone.

`m1_service` specifies a service contract:

- `maintain` preserves M1 validation and commit on every frame, including rejection.
- `reset_on_reject` explicitly clears WorldState before current precheck/commit;
  the normal commit contract then initializes current anchors and feature records.
- `output_only` explicitly clears WorldState and skips M1 on rejection. The next
  frame that needs M1 validation starts with an empty manager; no stale anchors,
  evidence, pending precheck or feature version survives. StreamPETR memory is
  still maintained normally.

The last two contracts discard world history and must not be presented as an
optimization preserving all M1 semantics. They require the gate explicitly enabled.
Use `worldstream_m2_camera_on_demand.py` for reset-on-rejection and lazy M1 reentry.
`worldstream_m2_camera_output_only.py` explicitly disables M1 for the current-output
service; this matches the final balanced Auto benchmark without WorldState.

Offline tools are under `tools/worldstream_m2/rearchitecture/`; the separate
`worldstream/m2/approximate_probe.py` aligns patch content before current absolute
position embedding for feasibility only. It cannot certify RoPE-dependent features,
dynamic objects or occlusions. No production code imports or invokes this probe.

See [experiment report](../outputs/module2_rearchitecture/experiment_report.md),
[feasibility](../outputs/module2_rearchitecture/feasibility_report.md), and
[numerical attribution](../outputs/module2_rearchitecture/numerical_diagnosis.md).

For services that do not require any M1 world state, it is also valid to set
`model.m1_enable=False` explicitly while selecting camera Auto. The executor still
performs full raw input equality and all downstream computation; M1 geometry is
not needed to certify identical EVA inputs. The balanced repeated-request benchmark
uses this explicitly labelled current-output contract. It is not a substitute
for the continuity-preserving configuration.

M1's branch feature timestamp describes the current assembled request tensor and
has `unknown/conservative` dependency scope. It is not a per-camera deep-compute
certificate. The separate M2 camera cache retains actual per-camera computation
frames/timestamps; neither assembly nor observation verification advances those
source timestamps.

Admission also accounts for measured validation: current M1 precheck/input adapter
plus the preceding frame's commit/output adapter form a simple maintenance estimate.
Camera Auto requires measured whole-backbone wall savings to exceed this estimate
as well as GPU benefit and downstream approval. Window Auto uses an optimistic
sum of approved per-block savings only to reject unaffordable requests; the exact
key/count checks still authorize individual execution. Invalid budget values fail
closed. Prior commit cost is an estimate, not a future-latency guarantee. Startup
weight hashing is measured separately from warmed service.
