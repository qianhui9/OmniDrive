# OmniDrive M1.2.1：历史观测恢复与运动补偿改进

## 一、任务目标

项目目录：`/data/qh/phdCode/work4/OmniDrive`

请直接基于当前项目代码，检查现有代码、配置、测试和 M1.2 实验结果，完成针对历史状态对应与运动补偿机制的下一轮改进。

本轮不是重新设计整个 M1，而是定位并解决 M1.2 暴露的核心瓶颈，优先提高真实场景中的有效历史观测覆盖率，同时保持现有几何验证、身份风险控制和事务安全机制。

当前重点检查以下问题：

1. 历史 RGB 三角化深度与下一帧重新提取的特征点之间缺乏稳定关联，导致有效深度利用率较低。
2. 原始 LK 光流、旋转补偿和深度初始化之间的候选选择策略较为保守，可能遗漏可以恢复的正确对应。
3. 动态运动预测依赖已完成资格认证的身份轨迹，而当前 Gate B 尚未通过，导致 C 组虽然开启动态运动预测，实际却没有可靠运动预测收益。
4. 现有离线评分中不可评分的对应点比例较高，难以充分判断新增候选究竟是否正确。
5. 当前改进尚未在多个独立场景中表现出超过 Baseline 的有效历史 Anchor 支持率。

此前实验报告中的深度漏斗、逐场景统计和动态运动预测计数仅作为排查线索。请首先核对当前分支的实际代码和实验产物，不要将历史统计直接当作本次运行结果。

## 三、第二阶段：改进历史深度关联与不确定性建模

针对 `ego_motion.py` 中历史深度通过像素最近邻匹配的机制，检查其与 `temporal_visibility.py` 特征点提取方式之间的兼容性。

### 3.1 增加必要的诊断

按场景、帧和相机统计：

- 历史特征点数量及可用深度记录数量。
- 下一帧特征点与历史深度的匹配数量、匹配率及距离分布。
- 一对一关联成功率、重复匹配和歧义匹配数量。
- 深度有效率、三角化视差角、深度不确定性及投影有效率。
- 深度初始化尝试次数、恢复跟踪次数、几何验证通过次数和最终获得局部支持的数量。

明确区分未执行、没有候选、候选全部被拒绝和真正通过验证的情况。

### 3.2 改进关联方式

如果当前诊断确认重新提取特征点导致历史深度无法稳定匹配，请将深度关联改进为具有明确跨帧来源的特征关联机制。

优先复用真实前后帧跟踪产生的关联关系；必要时结合局部描述子、光度一致性和几何约束建立跨帧匹配。

要求：

- 不依赖两个连续帧的特征点恰好落在几乎相同的像素位置。
- 不在不同物体表面或深度不连续边界之间随意插值深度。
- 对多对一、歧义匹配和来源不一致的记录保留拒绝机制。
- 继续绑定场景、帧、时间戳、相机、位姿、标定和状态版本。
- 对深度区间、投影位置及其不确定性进行合理传播；如果当前不确定性模型过于简化，请在可验证的范围内改进。
- 深度不足或不确定性过大时，必须保留 Unknown，不得伪造可靠的度量预测。

## 四、第三阶段：实现有限的多假设历史对应恢复

改进 `track_with_prediction()` 及其实际调用链。

保留并分别评估以下候选来源：

1. 原始 LK 光流。
2. 自车旋转补偿初始化。
3. 具有可靠历史深度的初始化。
4. 在确有必要且计算成本可控时，沿几何约束方向产生的有限搜索候选。

候选应使用独立的诊断记录，并通过现有必要验证，包括：

- 前后向光流一致性。
- 局部光度、纹理及描述子残差。
- 极线或其他适用的几何残差。
- 预测位置与实际测量位置的偏差。
- 候选间歧义、重复对应及空间支持。
- 动态区域、遮挡和有效视野约束。

不能仅因为某个候选的 LK 状态有效就将其认定为正确对应，也不能因为预测位置更接近历史投影就跳过独立验证。

当候选存在明确、可验证的质量差异时，允许选择更可靠的候选；当多个候选无法区分时，继续拒绝并保留 Unknown。

不得通过降低原有光流、几何、身份或物理资格门限来制造覆盖率提升。

请通过统一的候选评分与选择接口实现，避免不断叠加难以维护的特殊分支。只有真实执行路径使用的逻辑才算完成。

## 五、第四阶段：解耦搜索级动态运动预测与正式资格认证

检查 `world_motion.py`、`identity_continuity.py` 和 `state_manager.py`，明确当前动态运动预测为何依赖已认证身份以及校准的位置不确定性。

将运动信息明确区分为两个等级。

### 5.1 搜索级运动假设

在不违反现有状态来源约束的前提下，研究使用连续真实检测、暂定轨迹和实际自车位姿生成有限的动态物体搜索候选。

要求：

- 使用真实已提交的感知结果，不使用离线 GT、未来帧或标注速度。
- 不直接信任检测器提供的速度。
- 仅使用具有明确时间、场景、坐标系和来源绑定的历史观测。
- 对短历史、异常时间间隔、关联歧义、方向变化和加速度不确定性进行保守处理。
- 为搜索位置设置合理的不确定性范围和有限有效期。
- 搜索级预测只能帮助产生候选，不能单独证明物体身份、物理几何正确性或观测有效性。
- 不得将未经认证的运动假设直接写入可信状态、资格证书或正式身份历史。

如果需要使用暂定关联建立运动轨迹，必须使其与正式认证状态隔离，不能因为搜索成功就自动升级其身份资格。

### 5.2 资格级运动状态

继续保留现有资格级运动预测的严格要求，包括身份资格、状态版本绑定、位置不确定性校准和时间连续性检查。

只有独立资格流程通过后，才允许相关运动状态参与正式可信状态更新。

### 5.3 消融验证

至少保留以下可比较配置：

- Baseline：不使用新增运动补偿。
- A：仅自车旋转补偿。
- B：旋转补偿与历史深度。
- C：B 加搜索级动态运动预测。
- 如有必要，增加独立的多假设跟踪消融组。

记录每组中搜索级预测实际生成、成功匹配、通过验证及最终支持的数量。

如果 C 组没有真实激活搜索级运动预测，必须明确报告原因，不能仅根据配置开关开启就认定该功能已经得到验证。
