# 本轮关键实测诊断

这次没有达到“多个场景中提高有效历史 Anchor 且保持对应质量”的核心验收目标。以下原因来自本轮逐场景数据，不是直接沿用旧报告。

三个零覆盖场景的主要问题首先是声明资格，而非光流数量：`febc…` 的621个历史候选、`58af…` 的365个、`9303…` 的18个均为动态或运动未认证对象，没有静态 Anchor 的几何/运动资格。原有 `motion_known`、动态区域排除及独立资格门继续工作；新增搜索运动没有把它们默认成静止或可靠速度。因此这些场景的静态观察支持为零，与另行记录的有限身份提案并不矛盾。

`9a11…` 有624个符合投影条件的静态类相机视图：139个没有历史观察，485个描述子不匹配；新方法没有改变这两类失败。`20ec…` 仅5个符合条件视图，仍因缺历史、描述子、遮挡及局部支持不足而全部失败。不能靠增加全局对应点数量填补这些必要证据。

`c0d3…` 的562个符合投影条件视图中，Baseline 有198个被遮挡、214个描述子不匹配、101个局部历史支持不足，另有7个缺历史和3个缺对应来源。相对 C 组，额外裁剪对齐把一个描述子拒绝转为观察支持，最终39→40；五个零覆盖场景未改变。相对 Baseline 逐事件检查，则为新增3个、丢失2个，净增1个，并非全部保留旧支持后单纯增加。完整得失事件见 `support_event_changes.json`，新增事件的留出误差及残差见 `new_support_events.json`。这些只是有限裁剪观察事件，不证明物理身份、前景归属或度量几何。

新 B/C 保留全部436167个原始角点，另追加8224个此前实测深度点。有效历史深度相关相机人口中12281/153663个查询通过一对一关联，96个歧义拒绝；11005次 depth 初始化中6050通过LK、5548通过适用几何、4583通过完整局部门，最终仅12个由 depth 候选选中，其余多数与 raw/rotation 一致。raw 完整门失败后总恢复271点（旋转259、深度12），没有转化成多场景 Anchor 支持收益。

C 组742/2644次来源搜索生成了暂定世界坐标运动，但新几何边为0。独立无GT重建验证了全部742个来源/速度/区间；实际到达动态图像候选的33788个点，投影不确定性全部大于原有4px预算，最小7.205px、中位27.859px、P95 71.219px，实际初始化/成功匹配/局部通过/选中均为0。其余视图还被缺历史观察或当前投影不可用挡住。不能把742个运动假设说成动态跟踪已生效；没有放宽4px预算，可靠速度和正式运动历史未升级。

原离线对应评分：排除动态/遮挡后，Baseline为1421正确、206错误、69141不可评分；B/C为1484正确、238错误、72351不可评分。可评分子集约2.3%，各组人口不同，条件正确率约87.34%→86.18%。这既不能证明新增对应普遍错误，也不能支持“质量保持不降”；错误数确实增加，不能用点数增加宣称提升。三角化深度仍为有条件静态搜索先验，不是已校准的物理真值。

最终 Oracle 使用相同444391个源像素，只有19552个有合格稀疏源LiDAR参考。共享源参考人口中，raw/RGB/Oracle完整局部通过分别4908/4925/4667点；原评分正确数均为1779，错误数为125/125/77。独立深度及原有4px预测残差门剔除了48个可评分错误，但没有增加可独立评分的正确对应，完整通过人口还减少了241点，不能宣称覆盖率提升。外部深度并未证明后续LK/局部验证/遮挡门能恢复更多可靠 Anchor。Oracle不提交状态，Anchor反事实实验为 Not Run；传感器异步、稀疏表面和静态初始化假设使其不是数学上界。

复核发现早期 Oracle 工具未用4px预测残差及明确源深度范围门，已补齐后在 `main/oracle_strict/` 新目录完整重跑；原 `main/oracle/` 的4939点结果保留作诊断存档，不作为最终验收依据。39项相关测试已再次实际通过；此修复只涉及离线诊断，不改在线生产者或已提交状态。

所有数字保留逐场景原始计数与分母。详见 `main/fixed_anchor_diagnosis/`、`main/fixed_evaluation/*/funnel/`、`main/search_revalidation/`、`main/oracle_strict/`。扩展场景按预声明规则执行后另列于最终报告，不参与上述固定六场景数字。
