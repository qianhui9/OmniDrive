## 2. 实际失败分析与设计边界

先读取保存结果，未执行旧方法。`saved_failure_analysis.json` 保存逐个明确错误及前帧缓存几何。两次交通锥错误是同一对可评分实例的交换与换回；第一次检测中心跨帧仅移动约 0.0535 米，因此不能归咎于“移动太快、距离门太窄”。交通锥不在外部跟踪类别内。自行车错误同样缺少外部历史，不能用未对齐 ID 强行修复。

保存协议中快速运动为 0/115；2 米静态中心门与依赖认证才能启用的物理运动先验，构成明显限制，但旧日志没有逐边门控原因，不能证明全部 115 次都只由距离门造成。旧代码明确拒绝缺帧后的重新出现，且状态超过 1 秒被清除，另有独立的遮挡恢复问题。外部方法保存日志同时包含历史缺失、短轨迹、丢失/过期、候选竞争等原因，不能将其视为单一故障。

### 关联运动历史

每条轨迹最多 8 次观测、最多 256 条、最后观测起最多 3 秒；序列化体积与保守递归对象内存计数均限制为 4 MiB。历史只在原提交 worker 中更新；失败提交、放弃 precheck 均不发布。历史最后一项必须匹配锚点版本、帧、时间、中心、Scene、epoch、执行签名、类别及感知来源。

至少 3 次可靠观测后，以成对斜率中位数估计速度、以中位截距估计位置；最大历史残差与逐步速度不稳定性随预测间隔增长，全部消耗原距离预算。此不确定性是保守启发式预算，**不是校准的概率协方差**。不读取检测速度来估计关联轨迹。可靠历史仅接收独立端点的无竞争关联，或完整唯一且有实测正 ROI 支持的组件；竞争中的普通几何选择不延长轨迹。

### 几何、局部外观和未匹配

原类别、尺寸比例、Scene/来源/版本和时间约束保留。运动只改善合法几何残差，不赋予身份证明。外观比较实际对象投影 ROI，不使用全相机描述子；要求同相机/坐标空间、有效投影与时间、近似一致观察方向、受限区域尺度。明显近处投影遮挡、低纹理、缺描述子或视角变化返回 unknown。聚合最近 3 项可比较的历史局部描述，任一有效残差冲突即可否决，不用加权总分补偿冲突。

缺失证据保留为竞争边；只有整个竞争组件有完整、唯一、实测正证据时才替换关联。已筛选边再经带独立未匹配列的一对一分配；未匹配不被最大基数目标强制填充。已有唯一几何边可继续作为普通未认证关联；外观未知不被记录为成功外观。

### dormant 身份与缓存安全

dormant 仅保存轨迹/ROI 元数据，不保存 FeatureRecord、网络特征、图像或认证。重新出现必须同时具备有效轨迹预测、原几何预算、完整正 ROI 证据和无未解决竞争；不能恢复时允许新身份。Scene/epoch/执行条件变化通过原 reset 清除记录，TTL/数量/内存进一步限制生命周期。

恢复只继承身份字符串和关联历史，新状态使用当前实际几何；清除 last_verified、认证计数、物理认证和 identity_link_qualified，不恢复历史特征链接。过期 StateStore 锚点和特征依旧按原规则清理。关联运动从不写 `motion_history`、`motion_prediction` 或自动设置 `velocity_reliable`。M2 仍读取原 precheck 冻结的历史验证与自己的安全门，新关联不是复用资格。

## 5. 真实改进、退化及原因

逐关系核对：新增 1 个正确延续，同时丢失原有 7 个，净减少 6。丢失/新增的 frame 与 instance 清单在 `result_analysis.json`。3 个错误的 `(frame, previous_instance, current_instance)` 与保存结果完全相同，**没有新增明确可评分的错误合并**；unknown 仍不能证明正确，也不能证明没有潜在错误。

全程应用了 1494 个关联运动预测；ROI 共取得 147 条可测候选边，146 条不匹配，只有 1 条满足现有残差门，未带来实际 dormant 恢复。这说明本轮简单局部灰度描述在真实跨帧 ROI 下几乎不能提供可用正证据；只增加保守拒绝不足以改善召回。框内背景、视角/尺度变化及遮挡可能影响残差，但现有日志不足以将 146 条不匹配全部归为真实对象不同或某个唯一原因。

快速运动仍 0/115：新预测要求先建立 3 次可靠关联，若最初就一直超出原几何门，无法积累轨迹。不能用合成短时间种子测试成功宣称真实快速组改善。保守运动预算/外观否决及后续历史不足没有换来足够的新正确关系；帧级日志未保留逐条预测残差，无法精确分摊七次原正确关系损失到各个门，因此不做无证据的单原因归因。

全程物理认证数量 0，DQTrack 分支诊断为空。最大轨迹数 229，最大序列化记录 1,156,537 字节，最大保守内存计数 2,451,549 字节，均低于配置上限；这是单个提交快照的轨迹预算，不是整个 Python 进程的 RSS 上限。事务临时副本有有界额外内存。

本次 CPU 回放 M1 P50/P95 为 **126.106 / 707.530 ms**；保存原结果为 **100.867 / 365.905 ms**。未同轮重跑原方法，不能将差异当成受控配对开销，但新增历史复制、JSON 来源摘要、ROI 投影与内存计数没有展示成本优势。不是完整 OmniDrive E2E/GPU 性能测试。
