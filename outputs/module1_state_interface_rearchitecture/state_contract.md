# M1 computation state / M2 admission contract

Opt in with configs/worldstream_m1_source_linked_state.yaml and projects/configs/OmniDrive/worldstream_m2_source_linked.py. Legacy defaults and historical strict configurations remain available. Approximate/warped feature reuse is absent.

ComputationStateBundle is a Precheck snapshot. scene/frame/time/epoch/signature identify the current request. source_records refer exclusively to already committed history. source_frame_id/source_timestamp identify the observed physical image; computation_frame_id/computation_timestamp/computation_version identify actual feature production. These can differ. source_cache_version identifies the retained M2 cache publication, including later publications that contain older computed features.

A metadata-only FeatureRecord does not establish a retained tensor. computation_available requires an owned M1 tensor or a matching M2 cache receipt and known computation lineage. Pure image observations have null computation sources and computation_available=false. M1 does not own or copy M2 tensors.

observation_links contain actual source/current sample positions, RGB-derived grayscale photometric residuals, camera-time timestamps, local scope and unresolved two-view limitations. A dense candidate applies only to individually measured pixels; sparse LK applies only to measured centres. No bounding box fills, object ownership, Transformer equality or M3 task certification follow from these observations. Invalid calibration, time order, age or camera geometry prevents admission.

The lease shares max_state_age_s and the existing committed lifecycle. It never extends a feature's computation age when its verification frame advances. Last observed/verified timestamps refer to the committed observation used by Precheck. Source expiry, invalid timing, calibration changes, scene/signature changes and abandoned transactions revoke eligibility. Pixel conflicts remove their own candidate support. The no-extra-lease and lease-export ablations retain the same hard age gate, so they do not represent separate learned policies or independently tuned lifecycles.

RefreshContract uses preprocessed_image coordinates and lossless masks. Dirty and Candidate are disjoint; Unknown completes the partition. Known changed pixels take priority. Candidate has no skip authority. In the lightweight configuration, ordinary dense observations do not satisfy the optional strict Surface Constraints protocol: refresh_required_mask and exact_invalidation_mask therefore conservatively request full refresh. Running the original strict configuration keeps its original masks. Refresh Contract never substitutes inverse Candidate for legacy exact invalidation.

Runtime accepts forward(..., computation_state=bundle) as well as the existing M1Result argument. Aborting the issuing Precheck revokes both the result and its Bundle transaction status; standalone Bundle admission rejects aborted snapshots.

M2 source_linked admission checks current context, source cache publication, source frame, epoch, observation lease, actual computation ages, coordinate geometry and mask partition. It permits Unknown pixels to undergo independent Exact validation. Dirty pixels force updates. Candidate and Unknown both require finite equality of actual retained preprocessed inputs, complete patch receptive fields, closed window dependencies, full global dependencies, model/layout/device/version signatures and the existing cost/quality gates. Any forced refresh or aborted transaction wins. Camera-boundary Dirty conservatively forces a full camera-batch recompute.

Auto is the production configuration. Exact remains an explicitly forced engineering test mode, including numerical probes of local changes; it does not publish a downstream quality certificate. Existing unqualified nonzero local updates remain rejected by Auto.

M2 receipts include actual camera computation sources or early-block window sources, verification/cache publication context and versions. Reused sources retain their computation frame/version. Current downstream heads and full backbone outputs after global attention have current computation lineage. Receipts enter M1 atomically with Commit; missing or failed Commit cannot advance them. Cached tensors remain M2-owned. StateCache now allocates image snapshots and metadata before publication, closing a reproducible partial-publication failure on metadata allocation/OOM.

CheapAdmission rejects opportunities only. maintain keeps Precheck/Commit and the existing identity work; a rejected opportunity defers dense and optional surface verification, exports Unknown, and still updates committed camera/world history. reset_on_reject and output_only retain their explicitly different existing semantics. CPU-only source metadata adds no GPU image copy; lineage copies window IDs only for genuinely partial experimental/certified execution, avoiding transfers for zero-update and full-update production cases.

GPU follow-up version audit: computation_version_namespace identifies the producer. Camera cache entries always use the committed M2 camera-execution version, for newly computed and reused entries alike. feature_record_version separately records the M1 slot counter. source_cache_version advances with cache publication; the producer version remains unchanged while the same computed value is verified or republished. The recompute→reuse regression and live GPU Precheck snapshots verify this distinction.

The current-signature development cost refresh is zero-update-only. Profiling creates an unqualified record; fresh controlled full-task quality checks must pass before Auto reads it. The experiment never copies qualification from a differently keyed historical record. Natural driving, controlled repeat, experimental Exact qualification and qualified zero-update Auto results remain separate. Formal independent physical qualification is unchanged.
