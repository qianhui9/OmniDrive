# OmniDrive 改进项目运行指令

本地不再需要旧 `.git` 才能执行下述主实验命令。Native 审计采用校验后的独立源码快照；GitHub 更新与本地独立版本标识见 [源码溯源说明](../docs/provenance/README.md)。

本文以当前冻结的 **M1 + M2 + M3 / R0** 为研究主线。所有命令均从项目根目录执行，使用现有 `OmniDrive` 环境；本文件提供操作说明，不会自动启动实验、训练或修改权重。

## 1. 按任务选择入口

| 任务或条件 | 使用入口 | 说明 |
|---|---|---|
| 复现论文五种查询频率的 Native / R0 配对主实验 | 第 4 节 `frozen_main_benchmark` | 正式主入口，保留完整连续 Scene、独立 RNG 和完整 E2E |
| 仅检查已有主实验 | 第 5 节 `verify` | 需要完整冻结清单及原始收据；只有日志不够 |
| 重新计算主表、质量指标和图 | 第 5 节 `frozen_main_report` | 使用实际收据，不重新推理；会重写该目录的派生报告 |
| 对完整验证集运行 R0 或 Native 的规划/问答任务 | 第 6 节临时配置 + DDP | 固定 R0 参数，单卡也必须使用分布式启动器 |
| 官方 Detection / Lane 评价 | 第 7 节 | 完整验证集与连续流子集的结论分别记录 |
| 只执行视觉任务，不生成语言答案 | 第 8 节 | Native 去掉语言头的诊断入口，不能当作完整 R0 的性能结果 |
| CPU / RTX3090 全量回归 | 第 9 节 | GPU 版等待空闲，CPU 版显式屏蔽 CUDA |
| 检查进度、GPU、失败或目录占用 | 第 10 节 | 不终止其他用户任务，不按进度日志推定成功 |
| 原始模型训练或断点训练 | 第 11 节 | 独立参考任务，不属于冻结 R0 主实验 |

### 4.3 正式运行全部五种负载

```bash
taskset -c 0-3,6-31 env CUDA_VISIBLE_DEVICES=0 \
  /home/qh/miniconda3/envs/OmniDrive/bin/python \
  -m tools.worldstream_m123.frozen_main_benchmark main --root "$OD_R0_RUN"
```

| 编号 | 条件 | 既有负载定义 |
|---|---|---|
| S1 | Every-4 | 每 4 个视觉帧一个可寻址问题 |
| S2 | Every-2 | 每 2 个视觉帧一个可寻址问题 |
| S3 | Every-1 | 每帧一个问题，按既有顺序轮换类型 |
| S4 | Three-per-frame | 每帧 Category、Existence、Position 三问 |
| S5 | Mixed-three | 既有可寻址问题加当前原始自然问题的混合三问 |

这些条件由源码中的 `WORKLOADS` 和既有 `continuous_stream.question_schedule` 定义。当前 CLI **没有** `--workload S4`、`--frames`、`--scene`、`--resume` 或在线交互输入参数。执行一次 `main` 就是全部五种条件；不要虚构参数或改源码来跳过不利帧。

A 是 M1/M2/M3 全部关闭的原始 Native；C 是完整冻结 R0。每个执行臂按时间连续运行，Scene/负载/臂之间重置状态，按 Scene 与负载交替 A/C 顺序。无 QA 帧、冷启动和状态维护均进入 E2E。

### 4.4 自动收尾：官方 Lane 子集、测试、归档与重算


`finalize` 包含 CPU 和真实 CUDA 全量回归，不是纯 CPU 报告命令；会等待 GPU 空闲。它校验收据、生成报告、无损压缩本轮原始收据、从归档重算指标，并核验历史输出与权重。它不提交 Git。`completion.json` 的 `READY_FOR_GIT_REVIEW` 表示实验验证完成、等待人工检查提交，不表示科学结果仍在运行。

上述阶段不是幂等续跑接口：日志使用独占创建，重复执行可能报文件已存在。失败时保留当前证据，先定位原因；不能靠删除阶段目录后重复运行而把新旧结果混成一轮。

## 6. 单独运行 R0 / Native 的完整验证集任务

本节适合规划、自然问答和短驾驶动作等实际输出任务。它不等同于第 4 节的五频率配对协议，也不提供在线队列 SLA。R0 保留完整 M123 路径，参数不搜索。

### 6.1 设置任务并生成独立临时配置（CPU）

```bash
export OD_ARM=R0
export OD_TASK=conv
export OD_TASK_RUN=outputs/manual_r0_conv_run01
```

| 变量 | 可选值 | 含义 |
|---|---|---|
| `OD_ARM` | `R0` / `Native` | 完整 R0 / 关闭 M123 的原始模型 |
| `OD_TASK` | `conv` | 原始对话/VQA问题；含描述问题，不等同于 S5 |
| `OD_TASK` | `planning` | 原始开放环轨迹问题 |
| `OD_TASK` | `short` | 简短驾驶动作描述 |
| `OD_TASK` | `counter` | 反事实轨迹问题，需要 `data/nuscenes/eval_cf/` 的对应文件 |

例如运行 Native planning，应将以上三项改为 `Native`、`planning`、`outputs/manual_native_planning_run01`，然后重新执行下面的生成命令。每个任务必须使用新目录，防止原生答案文件缓存造成推理跳过。

下面只创建本次运行的配置与策略副本，不修改项目模型、权重或共用模板。它读取权威配置的全部字段，并调用正式冻结工具的完整 R0 参数读取函数，不依靠参数摘要拼装 R0。

```bash

  /home/qh/miniconda3/envs/OmniDrive/bin/python - <<'PY'

from pathlib import Path

arm, task = os.environ['OD_ARM'], os.environ['OD_TASK']

cfg.model.train_cfg = None

cfg.data.workers_per_gpu = 2
for split in ('test', 'val'):

            step['load_type'] = [task]
    cfg.data[split].pipeline = pipe

        m1_execution_mode=policy['M1']['execution_mode'], m1_config=policy['M1'],
        m2_enable=True, m2_config=policy['M2'], m3_enable=True, m3_config=m3)
else:

        m1_enable=False, m2_enable=False, m3_enable=False)
target = root/'effective_config.py'
cfg.dump(str(target))
loaded = Config.fromfile(str(target))
assert loaded.model.m1_enable == (arm == 'R0')
assert loaded.model.m2_enable == (arm == 'R0')
assert loaded.model.m3_enable == (arm == 'R0')
if arm == 'R0':
    assert dict(loaded.model.m1_config) == policy['M1']
    assert dict(loaded.model.m2_config) == policy['M2']
    assert dict(loaded.model.m3_config) == m3
```

### 6.2 单张 RTX3090 执行并导出答案/检测结果

```bash
taskset -c 0-3,6-31 env CUDA_VISIBLE_DEVICES=0 PYTHONPATH=. \
  HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
```

答案在 `$OD_TASK_RUN/answers/`，每个文件名是 sample token，读取内容时不要假定有 `.json` 后缀。检测格式化结果默认在 `test/effective_config/<运行时间>/pts_bbox/results_nusc.json`；`tools/test.py` 内部设置该路径，`--eval-options jsonfile_prefix=...` 不能按普通 MMDet 习惯覆盖它。并行任务需使用不同端口，但同卡仍应串行。

当前 `tools/test.py` 的非分布式分支和 `--out` 分支有显式断言，因此不要直接执行 `python tools/test.py ... --launcher none`，也不要加 `--out result.pkl`。`--format-only` 与 `--eval` 二选一。单卡 batch 保持 1，场景顺序不可打乱。

### 10.3 常见条件与处理

| 现象 | 原因或处理 |
|---|---|
| GPU 被占用，长时间无模型进度 | 查看 GPU 和日志，等待资源；不停止其他用户任务 |
| CUDA 不可见 | 检查主机终端/驱动访问，不能用 CPU 结果冒充 CUDA |
| `FileExistsError` | 输出目录或阶段已经存在；检查是否运行过，使用新目录，不盲删旧证据 |
| 找不到 `frozen_main_config.json` / 收据 | 结果目录不完整；恢复完整归档或新建一轮，不凭日志补造数据 |
| 配置/源码/权重哈希不符 | 检查当前代码版本与冻结记录；不修改冻结文件让校验“通过” |
| `tools/test.py` 非分布式断言 | 使用 6.2 的单进程 DDP 启动方式 |
| `--out` 断言 | 当前脚本未实现该保存分支，使用 `--format-only` 或 `--eval` |
| 生成答案似乎未重跑 | Native 会按答案文件是否存在跳过语言生成；更换任务输出目录 |
| 端口已占用 | 换未占用的 `--master_port`；不停止无关进程 |
| 显存不足 | 保持单卡 batch=1，确认没有其他任务；记录失败，不擅自改 R0 算法或权重 |
| 只想运行某天气/密度场景 | 当前主入口固定全清单后离线分层；没有天气筛选 CLI |

检查存储占用，不执行删除：

```bash
taskset -c 0-3,6-31 du -sh outputs/* test ckpts
```

优先使用 4.4 已校验的无损归档，保留完整收据和索引。不要删除权威 R0 目录、配置引用的 `resources/`、数据或权重来腾空间。具体清理范围另行确定，不在运行指令中加入批量删除命令。
