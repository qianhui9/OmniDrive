
# 项目内存和显存占用
结论：按 OmniDrive 官方配置原样运行，训练需要约 38,290 MB/卡显存，建议至少使用 8 张 48GB GPU；完整推理实际可以在单张 RTX 3090 24GB 上运行，但已经比较接近显存上限。

## 资源需求汇总

| 阶段 | 官方运行方式 | 单卡显存 | 主机内存 | 额外磁盘空间 |
|---|---|---:|---:|---:|
| 完整训练 | 8 卡，batch size 2/卡 | 实测峰值 38,290 MB，约 37.4 GiB/卡 | 至少 256GB，建议 512GB | 建议预留 100–150GB |
| 完整推理 | 官方命令为 8 卡，batch size 1/卡 | 估计约 20–23GB/卡 | 单卡至少 64GB，建议 96GB | 约 1GB/次 |
| 单卡 RTX 3090 推理 | 已在当前机器完成 | 小于 24GB，但余量有限 | 当前 62GiB 可完成 | 本次约 590MB |
| 仅3D检测、不生成VLM文本 | 需调整配置/代码 | 估计约 16–20GB | 约 48–64GB | 通常低于完整推理 |

这里的训练显存来自官方训练日志，不是理论估算。官方使用的是：

- 8 × NVIDIA A100-SXM4-80GB
- 每卡 batch size = 2
- FP16 混合精度
- 6 个 epoch，共 10,548 iterations
- 日志显存峰值：`memory: 38290`

`38290` 按 MMCV 的记录方式约为 38,290 MiB，即约 37.4 GiB。因此40GB显卡虽然理论上接近可用，但考虑 CUDA context、显存碎片和软件版本差异，余量过小，建议至少48GB/卡。官方训练命令和配置分别见[训练与推理教程](/data/qh/phdCode/work4/OmniDrive/docs/training_inference..md:1)和[官方配置](/data/qh/phdCode/work4/OmniDrive/projects/configs/OmniDrive/mask_eva_lane_det_vlm.py:21)。

## 为什么训练需要这么多显存

官方训练并不只是普通的3D检测模型，而是同时包含：

- EVA02 视觉骨干；
- StreamPETR 3D检测分支；
- 地图/车道分支；
- LLaMA-7B视觉语言分支；
- 最长2048 token的语言输入；
- LoRA rank 128；
- 反向传播激活、梯度和优化器状态。

配置虽然启用了FP16、视觉骨干 checkpoint 和 LLaMA gradient checkpointing，但峰值依然达到约37.4GiB/卡，相关配置见：

- 每卡 batch 2：[配置第21行](/data/qh/phdCode/work4/OmniDrive/projects/configs/OmniDrive/mask_eva_lane_det_vlm.py:21)
- `max_length=2048`：[配置第192行](/data/qh/phdCode/work4/OmniDrive/projects/configs/OmniDrive/mask_eva_lane_det_vlm.py:192)
- FP16：[配置第279行](/data/qh/phdCode/work4/OmniDrive/projects/configs/OmniDrive/mask_eva_lane_det_vlm.py:279)
- LLaMA gradient checkpointing：[misc.py](/data/qh/phdCode/work4/OmniDrive/projects/mmdet3d_plugin/models/utils/misc.py:232)

8卡DDP不会将37.4GiB模型显存平均切成八份。每个进程都有一份完整模型，因此关键约束仍然是每张卡至少容纳约37.4GiB。总GPU已分配显存约为300GiB，但它不能用“总显存相加”来判断单卡是否能运行。

## 推理显存

官方推理命令同样写的是8卡，但这主要是为了缩短6019个验证样本的运行时间，并不是模型必须依赖8卡才能装下。

当前项目已经在单张24GB RTX 3090上完成了完整推理，说明：

- 单卡推理峰值必然低于24GB；
- 实际合理估计约20–23GB；
- batch size 必须保持为1；
- 不能同时让这张卡运行其他占显存的进程。

推理脚本将测试 batch 固定为1，并在模型加载后整体移入GPU，见[tools/test.py](/data/qh/phdCode/work4/OmniDrive/tools/test.py:160)。它不是模型并行，8卡推理仍然是每卡各保留一份完整模型。

本次单卡3090完整推理：

- 6019个样本；
- 主推理耗时约17,103秒，即4小时45分钟；
- 检测结果 JSON：593,572,974 bytes，约566MiB；
- planning结果：6019个文件，合计约24MB。

因此，如果只是验证能否正常运行，单张3090 24GB已经足够；如果追求速度，可用多卡DDP把验证集分片。

## 主机内存需求

官方没有公布RAM峰值，所以这里需要结合加载流程估计。

当前权重大小为：

| 权重 | 大小 |
|---|---:|
| LLaMA/QFormer shard 1 | 9.29GiB |
| LLaMA/QFormer shard 2 | 3.85GiB |
| EVA/PETR初始化权重 | 1.18GiB |
| OmniDrive最终权重 | 17.84GiB |
| 权重总量 | 32.16GiB |

推理脚本先在CPU建立模型，并通过 `map_location='cpu'` 加载17.84GiB checkpoint，之后才执行 `model.cuda()`，见[tools/test.py](/data/qh/phdCode/work4/OmniDrive/tools/test.py:201)。因此启动阶段CPU里可能同时存在预训练模型、checkpoint以及反序列化临时对象。

建议：

- 单卡推理：64GB是已验证可运行的实际下限，96GB更稳妥；
- 官方8卡推理：至少256GB，建议512GB；
- 官方8卡训练：至少256GB，建议512GB。

8卡运行时会启动8个Python/DDP进程，每个进程都需要加载模型和数据标注，所以RAM消耗也不会简单保持在单进程水平。

## 磁盘空间

当前实际占用：

| 内容 | 大小 |
|---|---:|
| nuScenes + OmniDrive数据 | 772GB |
| 其中 `samples/` | 52GB |
| 其中 `sweeps/` | 333GB |
| OmniDrive权重 | 33GB |
| Conda环境 | 11GB |
| 单次推理检测JSON | 566MiB |
| 单次planning输出 | 24MB |

官方配置最多保留3个checkpoint，每个最终checkpoint约17.84GiB，因此训练目录稳定状态可能占用约54GiB。写入新checkpoint时还需要临时空间，连同日志、评测JSON和预训练权重，建议在现有数据之外至少预留100–150GB。当前 `/data` 约有1.1TB可用，磁盘空间足够。

## 对现有GPU方案的判断

- **2 × RTX 3090 24GB：不能直接运行官方训练配置。** 每卡24GB远低于官方约37.4GiB峰值，而且DDP不会合并两张卡的显存。推理可以正常运行。
- **4 × V100 16GB：无法运行完整训练。**
- **4 × V100 32GB：官方配置仍大概率OOM。** 将每卡batch降为1或冻结更多模块后可能接近可行，但这已经不是官方原配置，训练轮数、学习率和结果都要重新校准。
- **8 × A100 40GB：理论上接近，但余量很小。**
- **8 × 48GB及以上：适合原样复现。**
- **8 × A100 80GB：官方使用方案，最稳妥。**

本次按照 `system-profile` 的审计方式区分了官方日志实测值与估算值。没有修改或创建项目代码、配置及监控文件；只进行了只读资源统计，`/tmp/omnidrive_official_20250417.log` 是临时分析缓存。
